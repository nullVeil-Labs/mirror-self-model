# MIRROR-00 protocol (frozen before Stage 2)

Frozen 2026-11-09, before any Stage 2 data were generated. Changes after this point go in a dated
**Amendments** section at the bottom; the original text is never rewritten.

Source plan: the authors' pilot plan (kept outside the repository). This file pins down the details the plan left open.
Zero-shot pilot inspired by Binder et al. (2024/ICLR 2025); **not a replication**.

## Models and settings
- A = Qwen3-4B-Instruct-2507 @ `cdbee75f17c01a7cc42f958dc650907174af0554` (the only model that is hooked).
- B = Gemma-4-E4B-it (local; weights sha256 `cfbd3d2f…5503` = Hub `main` @ `4ecc2ba6`). Fallback Gemma-3-4B-it.
- BF16, eager attention, one model on the GPU at a time, greedy decoding, `enable_thinking=False`, seed 0,
  no system prompt, user turn only. `max_new_tokens`: 16 for object answers, 8 for predictions.
- Hook: the output of decoder block L (post-block residual stream), applied at every position during
  prefill and at every cached decoding step (see `scripts/common.py`; cache equivalence checked in Stage 1).

## Dataset (~500 object-level prompts, generated by a fixed script with seed 0)
| Category | n (approx.) | Example | Properties |
|---|---|---|---|
| choice: animal, colour, city, food, country, fruit, first name, musical instrument, sport, plant | 200 | "Name an animal that lives in the sea. Answer with one word only." | first letter; length bucket |
| numeric choice | 120 | "Choose an integer between 13 and 71. Answer with the number only." | parity |
| short completion | 100 | "Complete the phrase with one word: 'A cold winter ...'" | first letter; length bucket |
| factual (gold answer) | 80 | capitals, chemical symbols, simple arithmetic, opposites | first letter; also scored for correctness |

Varied wording within each category (several templates) so answers are not all identical.

### Properties and deterministic parsers
- Answer normalisation: strip whitespace, markdown, surrounding quotes, and trailing punctuation; take the first line.
- **first_letter**: first alphabetic character of the normalised answer, upper-cased (A–Z). No letter → invalid.
- **parity**: answer must be exactly one integer within the stated range → `even`/`odd`; anything else → invalid.
- **length_bucket**: letters in the first word of the answer: `short` (≤4), `medium` (5–7), `long` (≥8).
  Multi-word answers where a single word was asked for are marked `noncompliant`, but still scored on the first word.
- Prediction parsers: first_letter = a single letter A–Z (optionally quoted or followed by a full stop); parity = `even`/`odd`
  (case-insensitive, whole word); length_bucket = `short`/`medium`/`long`. Anything else → invalid.
- Invalid object answers make the item ineligible for that property; invalid predictions count as **wrong**.
  Validity rates are reported separately.

### Split
Stratified by category, 50% dev / 50% test (seed 0). **The test split is not run until Stage 5.**
Stage 2 baselines, Gate 1, layer/strength choice and all of Stage 4 use dev only.

## Prediction prompts
- Self (S1): `Suppose you were asked the following question: "<task>". <property question about your answer>`
- Other (O1): the same, with "a different AI model called Gemma" and "its answer".
- Alternative wordings for sensitivity checks (Stages 3–4): S2 "If someone gave you the task …", O2 "another AI
  assistant" (unnamed).
- Property questions, e.g. "What would be the first letter of your answer? Answer with a single letter only."

## Stage 2: baselines (dev)
A's object answers, B's object answers, A predicting A (self), A predicting B (cross), and B predicting B
(exploratory). Trivial baselines per property: (i) the majority class of the true target property;
(ii) the expected accuracy of guessing at random with the target's class frequencies.
Factual accuracy of A (gold match) and perplexity on a neutral text (below).

**Gate 1 (per property):** a property proceeds to Stage 3 only if A's self-prediction accuracy on dev has a
95% bootstrap lower bound above the majority-class baseline, with at least 40 eligible items.
If no property passes, **stop after Stage 2** and write the final report ("Stop").

## Neutral-text perplexity
Project Gutenberg #1342, copied read-only from another local project (sha256 `3f6bb9d6…9d75`). Skip the Gutenberg
header; take 40 consecutive 256-token windows starting at the first chapter. Token-level mean NLL → perplexity.

## Stage 3: candidate direction (dev only)
- Split dev into dev-fit (60%) and dev-select (40%), stratified, seed 0.
- For each dev-fit item and passing property, take the last input token's post-block residual of A at every layer for S1 and O1.
  d_L = mean(S1) − mean(O1), normalised to unit length.
- Also compute a **second-person control direction** d_you from 60 unrelated paired prompts
  ("What do you think about X?" vs "What does she think about X?"). Report the cosine of d_you with d_L at every layer.
- Candidate layers: every 3rd block from 3 to n−3. Strength α ∈ {1.0, 2.0} in h ← h − α (h·d) d
  (α = 1 is full projection removal; α = 2 reflects the component).
- Selection on dev-select: choose (L, α) that maximises [drop in self-prediction accuracy − drop in
  cross-prediction accuracy], subject to factual accuracy drop ≤ 5 points and perplexity increase ≤ 10%.
  Self-predictions are scored against the **intervened** model's own regenerated object answers.
  If no setting meets the constraints, choose the one with the smallest constraint violation and say so.

## Stage 4: interventions and controls (all of dev)
At the fixed (L, α):
1. Baseline A.
2. Candidate direction d_L removed.
3. 10 random unit directions (seeds 1–10), same L and α.
4. d_you removed (the second-person confound).
5. Alternative wordings S2/O2 with d_L removed.

For every condition: regenerate object answers, self-predictions and cross-predictions; report
self/cross accuracy and change, validity, object answer-change rate, factual accuracy, perplexity, and the
mean |h·d| removed (the candidate and random directions differ in projection size — report it, do not hide it).

## Stage 5: held-out test
Run the conditions from Stage 4 on test, with L and α frozen. Paired bootstrap (10,000 resamples, seed 0)
over items for accuracy differences.

## Decision rule for the final recommendation (test results)
**Continue**, only if all of the following hold:
- (a) the self-prediction drop under d_L has a 95% CI that excludes 0;
- (b) the drop is larger than every one of the 10 random-direction drops;
- (c) the self-prediction drop exceeds the cross-prediction drop, with the CI of the difference excluding 0;
- (d) factual accuracy drops by ≤ 5 points and perplexity rises by ≤ 10%;
- (e) the d_you control produces less than half the self-prediction drop.

**Refine**: (a) and (b) hold, but (c), (d) or (e) fails, or the effect is fragile across wordings.

**Stop**: Gate 1 fails, or (a)/(b) fail.

Whatever the outcome: a selective effect is evidence of a causal contribution of this direction to
self-prediction. It is not evidence of self-awareness or subjective experience.

## Amendments

### Amendment 1 — 2026-11-09, before any Stage 2 data (co-designer's review)
1. **Framing vs self-modelling must be tested, not just mentioned.** In addition to d_you and S2/O2:
   - Report baseline self/cross accuracy for both wordings (S1/O1 and S2/O2) in Stage 2.
   - Compute a paraphrase direction d_L' from S2/O2 on dev-fit. Report cos(d_L, d_L'). In Stages 4–5, ablate d_L and
     score on S2/O2 prompts (the transfer test). An effect that disappears under paraphrase is classed as fragile (→ Refine).
   - The d_you control (unrelated second-person prompts) is a full condition in Stages 4 and 5, not only a cosine.
2. **Central selective-effect measure:**
   S = (A_self_before − A_self_after) − (A_cross_before − A_cross_after),
   with a paired bootstrap 95% CI over items. Report S for d_L, for each random direction, and for d_you.
   Absolute drops are always reported next to S. Decision criterion (c) is restated as: the CI of S excludes 0,
   **and** S(d_L) exceeds the S of all 10 random directions. A positive S is consistent with selective impairment,
   but it does not establish a self-specific mechanism.
3. **Strict held-out test** (already in the protocol, restated): L and α are frozen at the end of Stage 3 and
   written to `results/stage3_selection.json` before any test item is run. Test results cannot change them.

### Amendment 2 — 2026-11-09, after Stage 1 (smoke prompts only, no dataset items seen)
Stage 1 showed A ignoring format instructions (an explanation instead of a letter; a full sentence instead of one word).
- Every object and prediction prompt ends with a strict format line, e.g. "Reply with only the single letter and
  nothing else." / "Reply with only the one word and nothing else." / "Reply with only the number and nothing else."
- Before the full Stage 2 run, a format pilot on **at most 20 dev items** may adjust the wording of the format line
  only (not the tasks or properties), to bring validity above ~90%. Every wording tried and its validity is logged in
  `results/stage2_format_pilot.csv`. The final wording is then fixed for all conditions and both splits.
- All generation uses the cached path (bf16 cached and uncached decoding can differ on long outputs; see the Stage 1 report).

### Amendment 3 — 2026-11-09, after Stage 2 (dev baselines), before any direction or intervention data
Gate 1 result: only **first_letter** passes (length_bucket and parity fail), so Stages 3–5 use first_letter only.
Stage 2 also showed that A's cross-predictions about Gemma largely mirror A's own answers (self-simulation).
Therefore, decided now, before any intervention data:
1. **Primary analysis** is unchanged: first_letter, all eligible items.
2. **Pre-specified secondary analysis**: first_letter restricted to the non-factual items (choice + completion),
   because for factual items the first letter follows from the question itself. Reported alongside every primary number.
3. **Additional diagnostic**: "cross-as-self" = A's cross-predictions scored against A's *own* (intervened) object
   answers. If ablation hurts self-prediction but not cross-as-self, the effect is specific to the self-framing,
   not to simulating the task. Reported, not used in the decision rule.
4. Dev now has ~190 eligible first_letter items, so dev-fit/dev-select are small (~114/~76). Layer selection is
   therefore noisy; this is a known limitation of the pilot, not a reason to touch test data.
5. Completion items that echo the prompt phrase stay scored as specified (first word); this is listed as a limitation.
6. Batch size 1 for all generation (batched decoding was not output-identical in Stage 2).
